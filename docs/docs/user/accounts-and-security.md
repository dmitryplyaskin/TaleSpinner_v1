# Аккаунты и безопасность

В TaleSpinner есть два режима доступа: `local` и `public`. В обоих можно создать
сколько угодно аккаунтов, а данные каждого аккаунта изолированы на сервере:
чаты, профили и персоны, World Info, пресеты, настройки LLM/RAG, API-токены и
загруженные файлы принадлежат текущему пользователю.

## Локальный режим

`TALESPINNER_ACCESS_MODE=local` подходит для доверенного компьютера.

- Пароль аккаунта можно оставить пустым.
- Единственный аккаунт без пароля открывается автоматически.
- При нескольких аккаунтах приложение показывает выбор пользователя.
- Пароль можно добавить позже в менеджере аккаунтов.
- Администратор может создавать, отключать и настраивать другие аккаунты.

Локальный режим упрощает вход, но не отключает изоляцию данных. Не публикуйте
его порт в интернет: backend по умолчанию слушает только loopback именно по этой
причине.

## Публичный режим

Публичный режим включается только полным набором настроек. Пример:

```env
TALESPINNER_ACCESS_MODE=public
TALESPINNER_SESSION_SECRET=<случайная строка длиной не менее 32 символов>
TALESPINNER_SETUP_TOKEN=<отдельная случайная строка длиной не менее 16 символов>
TALESPINNER_TRUST_PROXY=true
TALESPINNER_LAN_MODE=true
TALESPINNER_CORS_ORIGINS=https://talespinner.example.com
TALESPINNER_ALLOW_REGISTRATION=false
TOKENS_MASTER_KEY=<стойкий отдельный ключ>
```

Размещайте backend за reverse proxy, который завершает HTTPS. Передавайте
запросы в TaleSpinner только от этого proxy и не открывайте внутренний порт
напрямую. `TALESPINNER_CORS_ORIGINS` должен содержать точный HTTPS-origin
интерфейса без `*`.

При первом запуске введите значение `TALESPINNER_SETUP_TOKEN` в поле кода
первоначальной настройки. Этот токен не является паролем администратора:
храните его вне браузера и используйте также для аварийного восстановления
пароля администратора.

Публичный режим обязательно включает:

- пароль не короче 10 символов;
- `HttpOnly`, `Secure`, `SameSite=Strict` session cookie;
- проверку HTTPS и доверенного proxy;
- CSRF-защиту изменяющих запросов;
- ограничение неуспешных попыток входа;
- одинаковую ошибку для неизвестного, отключённого и неверно введённого аккаунта.

Если обязательный secret, setup token или proxy trust не настроен, сервер
завершает запуск с ошибкой.

## Управление аккаунтами

Менеджер аккаунтов позволяет:

- создать пользователя или администратора;
- изменить собственный пароль;
- администратору сменить роль, отключить аккаунт или сбросить его пароль.

Отключение аккаунта и смена пароля отзывают его активные сессии. Последнего
активного администратора нельзя отключить или понизить.

`TALESPINNER_ALLOW_REGISTRATION=true` открывает API
`POST /api/auth/register` для самостоятельной регистрации обычных пользователей
в публичном режиме. Встроенный интерфейс сейчас создаёт аккаунты через
администратора. Оставьте значение `false`, если внешние клиенты не должны
регистрировать аккаунты самостоятельно.

## Обновление существующей установки

Первый созданный аккаунт получает legacy scope `global`, поэтому видит данные,
которые существовали до появления системы пользователей. Перед миграцией
TaleSpinner автоматически создаёт согласованную копию SQLite в
`<каталог БД>/backups/db-pre-user-accounts-*.sqlite`. Повторный запуск не создаёт
новую копию после успешной миграции.

Перед обновлением облачной установки всё равно сохраните отдельный backup
каталога `DATA_DIR`, включая SQLite, media и файловые настройки.
